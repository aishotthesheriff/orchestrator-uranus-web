# Legacy Prompting System Deprecation - Engineering Plan

## Overview

This plan executes the deprecation of the legacy prompting system in favor of PCE (Prompt Composition Engine). The migration is approved for breaking changes and temporary non-functionality periods. Frontend and backend changes must be coordinated.

**Timeline**: 3-4 weeks (with 1-2 week buffer for unexpected issues)  
**Risk Level**: Medium-High  
**Approved**: Breaking changes and non-functionality periods are acceptable

**Philosophy**: Remove legacy code immediately. If PCE has issues, they will surface and be fixed. No fallbacks - all failures throw errors and are logged with full context.

**PCE Image Generation Preserved**: The plan removes template-based fallbacks but PRESERVES the PCE image generation system:
- PCE image stage (`runImageStage`) continues to generate `imagePrompt` using `server/pce/imagePrompt.txt`
- `generateImagePrompt()` in `contentRouter.ts` is preserved and remains the primary image prompt generation path
- Only template-based fallbacks (using `selectImageTemplate`) are removed
- The `imagePrompt` generated by PCE is the only source for image prompts after deprecation

## Error Handling Philosophy

**No Fallbacks**: All failures should throw errors and be logged with full context. No fallback mechanisms of any kind.

1. **PCE Stage Failures**: If any stage (master, narrative, image, actions) fails:
   - Log error with full context: stage name, input data, error type, expected vs actual output, stack trace
   - Throw error immediately - do not fall back to legacy or any other mechanism
   - Ensure errors are actionable for developers

2. **JSON Parsing Failures**: If PCE response cannot be parsed:
   - Log detailed error: expected JSON structure, actual response, parse error details
   - Throw error - do not attempt fallback parsing or use default values

3. **Image Prompt Generation**: If PCE image stage fails to generate `imagePrompt`:
   - Log error with full context
   - Throw error - do not fall back to template-based generation

4. **Action Generation**: If PCE actions stage fails:
   - Log error with full context
   - Throw error - do not provide fallback actions or hardcoded defaults

5. **Network/LLM Failures**: For transient failures (timeouts, rate limits):
   - Implement retry logic with exponential backoff
   - After retries exhausted, log error with full context and throw - do not fall back
   - For non-transient failures (parse errors, validation failures), throw immediately with error logged

6. **Error Logging Requirements**: All errors must include:
   - Stage name (master, narrative, image, actions)
   - Error type (parse, validation, network, timeout, etc.)
   - Input context (game state, user preferences, etc.)
   - Expected vs actual output
   - Full stack trace
   - Timestamp
